# EventFlow commit skill

## Authorized author identity

    user.name  = {GIT_USER_NAME}
    user.email = {GIT_USER_EMAIL}

Read from the repository's local Git config. If either is empty, stop and ask
the maintainer. Never invent an email, never impersonate, never copy
credentials. Commits carry this single author: no `Co-Authored-By`,
`Signed-off-by` or "Generated with" lines, ever.

## What this skill may do without re-asking

1. Run the lint command (`{LINT_COMMAND}`) and the tests (`{TEST_COMMAND}`).
2. Run `git diff --check` for whitespace and conflict markers.
3. Stage an explicit allowlist of changed source/test/config paths.
4. Re-read `git diff --cached --name-only` and abort on anything unexpected.
5. Create a descriptive commit with the authorized identity.
6. Push the tested milestone fast-forward to `{REMOTE_BRANCH}`.

Commit at milestones: a coherent, tested unit of work with its tests. Aim for
meaningful commits, not commit spam and not one giant drop.

## What always needs separate approval

Never, without a fresh explicit request from the maintainer:

- merge, rebase, amend, force-push, change remotes, rewrite history, or open
  pull requests;
- reconcile a diverged `{REMOTE_BRANCH}` (the push tool refuses and stops);
- commit protected paths without `--approve-protected`;
- commit generated data, datasets, secrets, or ignored files;
- commit with failing tests or lint (`--skip-tests` only on explicit request);
- `git rm --cached` anything;
- `git add -A`, `git add .`, or any wildcard staging.

## Hard refusals

Refuse to stage, even if force-added previously:

- `*.md`, `*.markdown`, `*.mdx` (all of them, including README.md)
- `planning/`, `.planning/`, `plans/`, `docs/planning/`, `docs/plans/`
- `*_PRD.*`, `*.prd`, `*.plan`
- `.claude/`, `.agents/`, `.venv/`, `venv/`, `.env*`, `*.pem`
- datasets (`data/`, `*.zip`, `*.npy`, `*.parquet`, `*.csv`, `*.csv.gz`)
  outside small `tests/fixtures/` excerpts

Public documentation goes in `README.rst`. Shared results go in `.json`,
`.csv` under `tests/fixtures/`, or `.rst`.

## Commit message format

    <type>: <description>

    <optional body: what changed and why, measurements if performance-related>

Types: feat, fix, refactor, docs, test, chore, perf, ci. Subject on one
line, at most 100 characters.

## Mechanics

Use the tracked helper rather than raw git plumbing:

    .venv/bin/python -m tools.commit_safe --dry-run \
        --message "test: add window index parity cases" \
        --path tools/windows.py --path tests/test_windows.py

Drop `--dry-run` to commit; add `--push` to push the milestone. The helper
enforces every rule above and exits non-zero with a report if anything is
off. Regenerate this file with `python -m tools.bootstrap_commit_skill`
(`--check` verifies the prerequisites without writing).
